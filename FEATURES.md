# ClientSynth — Product Feature Sheet

> **A multi-tenant SaaS platform for generating realistic synthetic data using AI — and the Digital Twin population engine for the DeeperPoint ecosystem.**

| Icon | Meaning |
|:---:|---|
| ✅ | **Implemented** — working in the current codebase |
| 🟡 | **Partial** — infrastructure exists but integration incomplete |
| 🔜 | **Planned** — on the development roadmap, not yet built |

---

## ⚠️ Ethical Usage Restriction

Synthetic profiles generated by ClientSynth must **never** be used simultaneously with real user profiles in a live marketplace. They are for populating prototype websites for testing and demonstration **only**. A sponsored real-world marketplace must be built without synthetic users — recruitment is the sponsor's responsibility.

## Data Generation Pipeline

| | Feature | Description |
|:---:|---|---|
| ✅ | **AI-Powered Field Generation** | Context-aware value generation via OpenRouter. Per-field prompts, system prompts, example data awareness, batch generation with retry logic. |
| ✅ | **17+ Field Types** | Name, email, phone, company, address, date, number, text, image, PDF, enum, boolean, URL, JSON, custom AI — covering most synthetic data needs. |
| ✅ | **Job Processor** | Production-grade batch processing with configurable batch sizes, exponential backoff retry, recovery states, real-time pause/resume/cancel, and progress tracking. |
| ✅ | **Deterministic Fallbacks** | When AI generation fails, the system falls back to deterministic generators for common field types (name, email, phone, company, date, industry) — no blank records. |
| ✅ | **De-Duplication** | Automatic detection and avoidance of duplicate records within a generation run. |
| ✅ | **Persona Contexts** | Scenario-based generation via `PersonaGenerator` — ensuring coherent populations where fields are internally consistent (a person's job title matches their industry and company type). |
| ✅ | **Rule Validators** | Cross-record logic enforcement — inter-record relationships and constraints are validated during generation. |
| 🔜 | **Conditional Field Generation** | Field values depend on other field values in the same record (e.g., "state" depends on "country"). |
| 🔜 | **Computed / Derived Fields** | Fields calculated from other generated fields (e.g., `full_name` = `first_name` + `last_name`). |
| 🔜 | **Multi-Model Strategy** | Different AI models assigned to different field types within the same job — cheap models for simple fields, expensive models for narrative text. |
| 🔜 | **Locale-Aware Generation** | Culturally appropriate names, addresses, phone formats, and certifications for specific countries and regions. |
| 🔜 | **Time-Series Data** | Generate data that changes over time — seasonal production volumes, price fluctuations, availability windows. |

## Schema Intelligence

| | Feature | Description |
|:---:|---|---|
| ✅ | **Visual Schema Designer** | Drag-and-drop schema builder (24KB component) with field type selection, prompt configuration, constraints, and ordering. |
| ✅ | **Schema Discovery from Files** | Upload an existing data file (CSV, JSON, XLSX) and the system automatically infers a schema — field names, types, constraints, and enums. |

| ✅ | **Universal File Parser** | Parses CSV, JSON, XLSX, and other tabular formats for schema discovery with validation and error reporting. |
| 🔜 | **Schema Versioning** | Track schema changes over time with diff history and rollback capability. |
| 🔜 | **Schema Import from Database** | Connect to an existing PostgreSQL or MySQL database and infer schemas from table structures. |
| 🔜 | **Pre-Built Schema Templates** | Common data shapes (e-commerce customers, healthcare patients, financial transactions, real estate listings) that users can start from immediately. |
| 🔜 | **Public Schema Marketplace** | Users can publish, share, and discover community-contributed schema templates. |

## Scope Boundaries

ClientSynth generates synthetic data. It does **not**:

- **Run the marketplace** — that is Cosolvent's matching engine
- **Host real user profiles** — synthetic profiles must never coexist with real participants in a live marketplace
- **Configure marketplace rules** — that is MarketForge and `marketplace.yaml`
- **Curate domain knowledge** — that is CommonContext

ClientSynth's value is in making every other tool in the ecosystem **testable** with realistic populations before real users arrive.
